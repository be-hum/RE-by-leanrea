## 원칙
분석 목표는 "특정 값 찾기"가 아니라 "흐름 해석"이다. 입력/트리거 -> 처리(변환, 상태, 분기) -> 출력/부작용(비교, 저장, 통신) 경로를 먼저 설명하고, 관심 대상 값(워게임의 정답 입력, 일반 프로그램의 키, 엔드포인트, 설정값, 프로토콜 필드 등)은 그 해석에서 따라 나오는 결과로만 제시한다.

**Why:** reversing.kr 6문제 회고에서 "결과가 읽히니 정답이고 가정도 맞다"는 순환 검증을 반복했다. 해를 고르는 기준과 가정을 검증하는 기준이 같아서 사실상 검증이 없었다(2026-10-29). 사용자는 이 방식을 워게임에 한정하지 않고 일반 프로그램 RE의 동작 구조 확인 목적에도 똑같이 적용하길 원한다.

**How to apply:**
- 노트와 답변에서 흐름(진입점, 함수, 상태, 데이터 경로)을 먼저 쓰고, 값 도출은 뒤에 둔다.
- 흐름의 각 단계는 코드 근거(주소, 심볼, 디스어셈블, 질의 결과)로 확인한다. 결과가 그럴듯하다는 이유로 가정을 승인하지 않는다.
- 후보가 여럿이면(해, 분기, 버전별 경로) 전부 제시하고, 하나를 고른 기준은 추정이라고 표시한다.
- 확인하지 못한 구간(라이브러리 함수 가정, 타입 변환 의미, 런타임 의존 값)은 열린 질문으로 남긴다.
