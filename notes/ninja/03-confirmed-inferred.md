# 확인 / 추정 / 미확인

## 확인
1. 로그 경로: `.ninja_log`, 빌드 디렉터리가 설정돼 있으면 `<builddir>/.ninja_log`(0x41010c, 0x43973c="/").
2. 로드 시간은 메트릭 `.ninja_log load`로 측정(메트릭 켜짐일 때만, 0x40fcd8).
3. `fopen(path,"r")` 실패 시 ENOENT면 메시지 없이 반환 2, 그 외는 `strerror(errno)`를 err로 반환 0(0x40fd87).
4. 읽기 버퍼 256 KiB(0x40000), `\n`으로 줄 분리, 줄이 버퍼 경계에 걸리면 `memmove` 후 `fread`로 이어 읽음.
5. 첫 줄에서 `sscanf("# ninja log v%d\n")`로 버전을 읽음. 파싱 실패도 버전 0으로 남아 "too old"로 처리.
6. 버전 <= 6: "build log version is too old; starting over", 파일 닫고 `unlink`, 반환 2(0x40f8ee, 0x40fee5).
7. 버전 > 7(정확히는 != 7): "build log version is too new; starting over", 같은 처리(0x40f8fa, 0x40ff15). 현재 버전은 7.
8. 줄 형식: 탭 구분 5필드 `시작<TAB>종료<TAB>mtime<TAB>출력경로<TAB>해시`. 시작·종료 `strtol` 10진, mtime `strtoll` 10진, 해시 `strtoull` 16진(줄 끝까지).
9. 탭이 4개 미만인 줄은 메시지 없이 건너뜀(헤더 줄도 이 경로로 무시됨).
10. 항목은 출력 경로 키 해시맵에 저장, 같은 경로가 다시 나오면 기존 항목을 덮어써 나중 줄이 이김.
11. 항목 필드: 경로, 명령 해시(u64), 시작·종료(32비트), mtime(64비트). 항목 크기 0x38.
12. 줄 수와 고유 경로 수를 셈. EOF에서 줄 수 > 100이고 줄 수 > 고유 수 × 3이면 재작성 필요 플래그 설정(0x40f946~0x40f961).
13. 빈 파일(아무것도 못 읽음)은 반환 1(성공), 재작성 플래그 없음(0x40fea0).
14. 호출자: 반환 0이면 Error "loading build log <path>: <err>"로 실패. err가 비어 있지 않으면(starting over 등) Warning으로 출력하고 계속(0x4102e9, FUN_00417730).
15. 재작성 전용 모드(`-t recompact` 계열로 추정되는 호출 인자)에서는 로드 결과가 2가 아니면 재작성을 수행하고 실패 시 "failed recompaction: %s".
16. 일반 모드에서 재작성 플래그가 켜져 있으면 열기 단계에서 재작성하고 실패 시 "opening build log: %s"로 실패.

## 추정
17. 반환값 0/1/2는 각각 로드 오류 / 성공 / 로그 없음(새로 시작 포함)이라는 상태 열거형이다(값은 확인, 이름·의미 구분은 추정).
18. 일반 모드의 재작성은 dry run이 아닐 때만 한다(this+0x10 설정 객체의 +4 바이트를 dry run 플래그로 추정).
19. 경로를 빌드 로그 객체(+0x38)에 저장하는 것은 로그를 실제로 쓸 때 열기 위한 지연 열기다.
20. EOF에서 버전 <= 6이면 재작성 플래그를 세우는 분기는 헤더 판정 전에 EOF에 이르는 경우를 위한 것이다(도달 조건 미확인).
21. 해시맵은 open addressing 계열이며 FUN_004092d0은 시드 0x439440을 쓰는 문자열 해시다.

## 미확인
22. 줄에 탭이 5개 이상이거나 해시가 16진수가 아닐 때의 처리(코드상 `strtoull`이 앞부분만 읽음, 그 이상은 미확인).
23. 시작·종료 시각의 단위(ms 등). 바이너리 로드 코드에서는 단위가 드러나지 않음.
