# B-010 사전 등록: ninja `.ninja_log` 로드

## 대상
- `targets/ninja/ninja`(ninja-linux.zip v1.13.2 안). 소스 `analysis/ninja/src.tar.gz`는 채점 전까지 풀지 않는다.
- 시험 변수: METHODS M-003 확장(문자열 참조 지점마다 앞 분기와 결과를 한 줄로). 고정: 사전 등록, M-008, Opus 단독, HOP 도구 없음.

## 범위 단계와 앵커 후보
| 단계 | 내용 | 앵커 후보 |
|---|---|---|
| L1 | 로그 파일 열기: 파일 없음/열기 실패 처리 | `.ninja_log` 문자열, `fopen` 계열 import, errno 비교(ENOENT) |
| L2 | 버전 헤더 읽기와 판정: 너무 오래됨/너무 새로움/정상 | `# ninja log v` 형식 문자열, `sscanf`/`strtol` 호출, 버전 상수 비교 `cmp ...,imm` |
| L3 | 한 줄 필드 파싱(필드 구분, 필드 수·형식 오류 처리) | `memchr`/`strchr`(구분자 `\t`), `strtol`/`strtoull`/`atoi` 호출 순서 |
| L4 | 항목 저장: 같은 출력 경로가 반복되면 어느 쪽이 남는지, 고유 항목 수 계산 | 해시맵 삽입 호출, 카운터 증가 |
| L5 | 재작성(recompaction) 필요 판단과 로드 결과 보고 | "recompacting"류 문자열, 줄 수와 고유 수 비교 상수 |

## 채점 규칙
- 소스 대조 대상: 같은 태그 소스의 build log 로드 함수와 그것이 직접 부르는 헬퍼. 범위 밖(로그 쓰기, 다른 로그 형식)은 채점하지 않는다.
- 항목 단위: 노트 03의 확인/추정 항목 하나 = 1항목. 판정: 맞음 / 추정 적중 / 누락(소스의 범위 안 동작을 노트가 언급하지 않음) / 오답.
- 누락 목록은 소스에서 범위 안 분기·기본값·오류 처리를 열거해 만든다. 소스 줄 번호는 `nl -ba`/`rg -n` 출력에서만 옮긴다.

## 판정 기준 (루트 CLAUDE.md 기본값)
- 누락 2 이하: M-003 확장 유효(추정 -> 확인 후보). 3~4: 불확실. 5 이상: 효과 없음.

## 알려진 교란 요인
- ninja는 널리 알려진 오픈소스라 모델 사전 지식이 결과에 섞일 수 있다. 바이너리에서 실측 근거(주소, 디스어셈블)를 댄 항목만 확인으로 쓰고, 근거 없이 "알고 있는" 동작은 추정으로 쓴다. 채점에서 근거 없는 적중은 추정 적중으로만 센다.
