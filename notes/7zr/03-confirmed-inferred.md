# 확인 / 추정 / 미확인 (소스 열기 전)

## 확인
1. 시그니처 바이트열 `37 7a bc af 27 1c`이 `.data` 0x48e4e8에 있음
2. 후보 검증 0x44dcbe가 6바이트를 개별 비교, 오프셋 12부터 20바이트의 체크섬을 오프셋 8의 4바이트와 비교
3. 체크섬 불일치 시 오프셋 8~31이 전부 0인지 검사하는 분기가 있음
4. 32바이트(`0x20`) 헤더를 읽음
5. 탐색 루프: 창 크기 0x7fe0(+0x20), 버퍼 0x8020, 후보마다 체크섬 확인, 일치 시 32바이트 복사와 위치 갱신
6. 쓰기 쪽 시작 헤더 초기화: 시그니처 6바이트 복사, `[6]=0`, `[7]=4`

## 추정
- 체크섬 = CRC32 (호출 19곳이고 `0x471330` 시그니처가 (버퍼, 길이)라는 것만 확인)
- 헤더 레이아웃 6+2+4+8+8+4와 각 필드 이름
- `[ebp+0xc]` = 최대 탐색 크기, 0이면 앞쪽 탐색 안 함
- 모두 0인 헤더 분기의 의미(버전 0.0이면 거짓)
- `[edi+0x10]` 호출 = Seek, `ds:0x47c1e4` = memmove
- 버전 `[7]=4`는 마이너 버전 4

## 미확인
- NextHeaderOffset/Size/CRC 검증과 읽기
- 버전 메이저 번호 검사 위치와 오류 처리
- 0x44dcbe의 반환값 의미 전체(모두 0인 헤더가 "빈 아카이브"인지)
- 오류 메시지 표를 쓰는 곳과 오류 코드 매핑
- 출처 진위
